🎙️ Cortex Speech

An offline-first desktop app that turns Kurdish (Sorani) audio into accurate, reviewable text — using a pipeline of AI models that transcribe, cross-check, and vote. Here is exactly how it works, from opening the app to closing it.

2The end-to-end journey — open to close

Everything below is the real, ordered pipeline the code runs. Each numbered step names the actual internal function and the models/tools it uses. Six phases take one audio file from your hard drive to a verified, exportable transcript.

A

Launch

— you open the app

App start & warm-up

The window opens, the Rust core opens your SQLite library, runs any pending schema migrations, warms the Silero VAD model, and probes whether the WSL 7B server is up on 127.0.0.1:8799. Health monitoring starts (checks snapshots, disk space, and missing models every 5 minutes).

B

Import & Prepare

— audio becomes clean, labelled speech chunks

1 File import / decode process_single_file

Your audio file is decoded to 16 kHz mono PCM, checked for empty/oversized buffers, and content-fingerprinted so the same recording is never imported twice. Long files stream-decode in 90-second windows instead of loading whole.

Symphonia decoderresampler → 16 kHzblake3 AudioFingerprint dedup

2 Voice-activity segmentation chunking::plan_speech_chunks

The Silero VAD v4 model finds where people are actually speaking and skips silence and noise. The file is cut into speech chunks bounded by min/max durations, splitting on pauses rather than mid-word. Each chunk becomes one segment.

Silero VAD v4 (ONNX via ort)merge/split heuristics

3 Speaker diarization compute_chunk_embeddings + cluster_embeddings

For each chunk a 192-dim speaker embedding is computed, and chunks are clustered by voice similarity to assign SPEAKER_00, SPEAKER_01… labels (who spoke each segment). Optional — used for podcasts/audiobooks.

CAM++ speaker-embedding (sherpa-onnx)online cosine clusteringfilename hint fallback

4 Gain normalization + optional denoise

Each chunk is RMS-normalized to −20 dBFS so quiet audio doesn't produce junk, then optionally cleaned by an AI denoiser. Audio-quality metrics (clipping ratio, RMS dB, SNR dB) are measured and stored for later confidence decisions.

normalize_pcm_rmsGTCRN denoiser (optional, sherpa-onnx)analyze_audio_quality
C

Transcribe

— speech becomes Kurdish text

5 Stage champion transcription build_segments_from_pcm

Every production chunk is staged for the OmniASR-7B Champion. The smaller CTC and MMS ASR implementations are diagnostic-only: import, batch transcription, and re-transcription never substitute them when the champion is unavailable.

OmniASR-7B Champion routefail-hard readiness gateno engine downgrade

6 Sorani text normalization normalizer::SoraniNormalizer

The raw transcript is normalized to canonical Kurdish orthography: folds Kaf/Yeh/Heh/hamza codepoint variants, handles diacritics/ZWNJ/tatweel, and optionally verbalizes numbers — producing a normalized_transcript stored alongside the raw one.

unicode-normalization (NFC/NFKC)g2p grapheme→phoneme

7 Persist to database persist_segments → speech_segments

Segments (raw + normalized text, speaker, timings, quality metrics, alignment offsets) are batch-inserted into SQLite. An AFTER INSERT trigger mirrors the text into the FTS5 full-text index so search works instantly; UPDATE/DELETE triggers keep it in sync.

rusqlite / SQLite (WAL)FTS5 segments_ftssegments_ai/au/ad triggers

8 Primary WSL 7B pass run_primary_wsl_pass_for_import

When the champion is primary, every placeholder segment is re-transcribed by the OmniASR-7B champion (base + Kurdish LoRA) on the GPU inside WSL. Results replace the placeholder and are recorded as the omniasr-wsl-7b hypothesis. If the server fails, the whole import rolls back rather than silently storing blank or downgraded text.

OmniASR-7B champion (WSL GPU)run_wsl_segment_transcriptprotects human edits
D

Refine & Correct

— fix known errors, build independent voters

9 LLM refinement / error-correction build_refiner + refine_with_context

The transcript can be polished by a language model that fixes phonetic slips. By default this is a LOCAL model — Ollama heretic-final:latest on 127.0.0.1:11434, fully offline. A cloud model (Gemini via OpenRouter) is used only if you opt in. A guard rejects rewrites that stray from the audio-grounded text.

LlmRefiner → local Ollama (default)Gemini 2.5 Pro (opt-in)few-shot from past corrections

10 LOOP-0 correction memory apply_loop0_firing

Learned per-word substitution memories — built from your own past corrections — automatically fix previously-seen wrong words with no retraining. On import it also "shadow-logs" whether it would have fired, without mutating anything (opt-in).

SubstitutionMemory + phonetic keycorrection_memory tableg2p-gated firing

11 Record transcript provenance populate_hypotheses

The champion draft and its exact model identity are stored as hypothesis evidence for review and export. Production does not run the smaller diagnostic ASR engines as extra voters; any historical hypotheses remain labelled provenance, not selectable fallbacks.

OmniASR-7B Championmodel-version identityhistorical provenance
E

Judge & Vote

— resolve disagreements, escalate only the hard cases

12 Acoustic forced-alignment score compute_acoustic_scores → ctc_score

Each transcript is force-aligned against its own audio to produce an acoustic consistency score — how well the text matches the sound. This feeds the confidence gate.

MMS Forced Aligner (ONNX)score_consistency

13 Out-of-distribution score compute_ood_scores → ood_score

Each clip is screened for weird acoustics (silence, white noise, music, distortion) using a zero-crossing + frame-energy-variance heuristic. An extra distrust signal for routing suspect segments.

OodDetector (ZCR + energy)

14 IRT Consensus Refinery fit_irt_consensus / run_consensus_refinery

The core disagreement-resolver. The multiple hypotheses are fused into one consensus transcript using Item-Response-Theory weighting — stronger models count more. It builds a per-word confusion network, votes per slot, and emits a consensus transcript plus an agreement confidence.

IRT ability learning (EM)confusion-network slotsphonetic diff

15 T0 gate — conformal calibration run_t0_gate / t0_gate_segment

Split-conformal prediction calibrates a per-SNR-bucket confidence threshold from verified segments. If a segment clears its threshold and passes hard vetoes (SNR/clipping, ≥2 distinct voters) it auto-accepts; otherwise it escalates to T1. The Autonomy Dial (Observe / Propose / Act+Confirm / Act Auto) controls whether it may auto-commit.

conformal nonconformity (5 SNR buckets)hard distrust vetoautonomy dial

16 T1 text judge jury::t1_judge

Disagreeing segments go to a text-based judge that uses tools — Kurdish lexicon plausibility, character n-gram perplexity (with a loop/repetition penalty), and optional web-search evidence — to localize the suspect word. Confident → commits a fix; hard → escalates to T2.

lexicon lookupn-gram perplexityweb-search (optional)

17 T2 audio-listener jury jury::t2_listener

The hardest cases go to a cloud audio-LLM that actually listens to the contested clip plus the T1 evidence, and returns a structured verdict. Self-consistency with N=3 samples guards against overconfidence; if the samples disagree, it must go to a human. Off unless you enable jury cloud opt-in.

Gemini 2.5 Pro audio (opt-in)self-consistency N=3prompt-injection hardening

18 Debate tier jury::debate::adjudicate

Only when T2 self-consistency fails: two diverse judges (a Gemini audio-LLM and a shadow re-ASR run) deliberate. A verdict is accepted only if both agree AND it survives swapping the hypothesis order (a position-bias guard); otherwise it escalates to human review.

Gemini audio judgeshadow re-ASR judgeswap-agreement guard

19 Verdict write-back write_verdict / update_segment_consensus_batch

The final verdict (auto_accept / jury_accept / jury_edit / escalated / human_*), the committed text, confidence, rationale and evidence are written back to the database and the search index. Human-verified corrections are never silently overwritten by later machine passes.

write_verdictFTS UPDATE triggerhuman-decision protection

Review the results

Use Review & Correct mode (one clip at a time: listen → fix → save-and-next) or the Review Inbox to adjudicate escalated segments with hypotheses, jury proposal and rationale. Click a word to hear it; low-confidence words are colour-coded. Edits auto-save and are undo/redo-able.

Session state (search query, sort, filter, selected clip) is persisted; the database keeps automatic snapshots you can restore from. Pending edits are flushed before the window closes. Reopen anytime and pick up exactly where you left off.

🔒 A note on the 7B champion and your privacy

The champion is a warm GPU server on your own machine, bound to 127.0.0.1:8799 inside WSL's private network. Your audio never leaves the device on the default path. If the server is down, transcription stops and offers only a champion repair/retry path — it never substitutes a smaller or cloud engine. (The cortex_7b_server.py file is machine-specific and lives outside the repo.)

4Local vs. cloud — the privacy contract

The app is offline by default. Nothing leaves your device unless you flip an explicit opt-in and configure an API key. Here are the only paths that can ever reach the internet — every one is off out of the box.

How the guarantee is enforced

A single choke point — effective_llm_mode() — downgrades any off-device route to a no-op without consent, and even blocks a "Local" mode secretly aimed at a remote host. API keys are never written to settings.json, never returned to the frontend, sent only in headers, and redacted from every error message. The webview CSP limits network access to self + ipc. There is no auto-updater and no telemetry.

Honest caveat

Today the privacy guarantee rests on source-level policy tests + code review, not a runtime network guard. A runtime "zero-outbound-socket" harness is planned but not yet built — so this is verified by inspection, not by a live network monitor.

6Five things to understand

It's a pipeline, not one model.

Audio → decode → Silero VAD cuts it into speech chunks → clean/denoise → transcribe → the 7B champion fills in the final text. Six phases, not a single black box.

The default brain runs entirely on your machine.

The 7B champion is a GPU server inside WSL, driven as a subprocess. On the default path, audio never leaves your device.

One champion transcribes; advisory checks never replace it.

OmniASR-7B produces the production draft. Optional consent-gated Gemini 2.5 Pro review can advise on hard clips, and the human decision remains final.

It fails loud, never silently downgrades.

If the champion is down, the app asks you what to do; a failed forced-7B import rolls back rather than storing blank text. Human-verified corrections are never overwritten by later machine passes.

Every cloud feature is off by default and gated twice.

The fixed Gemini 2.5 Pro advisory path needs both explicit opt-in and an API key. It is never a transcription fallback.
